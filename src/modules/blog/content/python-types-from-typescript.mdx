The shape I keep tripping on: in TypeScript, the type system *is* the compile step. If a function says it takes `User`, you cannot pass a `string` at the call site; the project will not build. In Python, the type hint is documentation that an external tool can verify if you ask it to. The interpreter does not check. The runtime does not check. If `mypy` is not in CI, the contract is not enforced.

That sounds like a downgrade, and from inside the TypeScript habit it feels like one. But after a few weeks of reaching for hints, ignoring them when they would slow me down, then turning mypy on for the modules I want to harden, I think the looseness is the point. Python lets you stage rigor where it matters.

## What I am doing about it

- Mypy strict mode on the modules that touch external boundaries: HTTP handlers, database queries, agent tool definitions. Anywhere the types are claims about the outside world, treat them as load-bearing.
- Looser hints in the modules that are still being shaped. The signature is a draft, not a contract.
- Reaching for `TypedDict` and `Protocol` more than I expected. Structural typing in Python feels closer to TypeScript than I thought it would.
